# Использование

Требуются Linux, Python 3, `getent` и `ip`. Для уведомлений в графической сессии нужен `notify-send`. Сторонние пакеты Python не требуются.

Укажите локальную папку для данных и выполните из папки проекта:

```bash
python3 monitor.py --data-dir '/путь/к/локальной/папке/данных'
```

`--data-dir` обязателен. В указанной папке создаются журнал `monitor.log`, история обнаружений `new-ips.tsv` и файл блокировки `.monitor.lock`. Значение должно указывать на вашу личную папку вне репозитория. Не публикуйте эти файлы: в них содержатся результаты DNS и информация о локальных маршрутах.

Список имён находится в `domains.txt`: один домен на строку, `#` начинает комментарий. Можно указать свой список:

```bash
python3 monitor.py --data-dir '/путь/к/локальной/папке/данных' --domains-file '/путь/к/доменам.txt'
```

На первом запуске все обнаруженные пары «домен — IPv4» записываются как новые. При следующих проверках новые пары дописываются, ошибки записываются в журнал, а предыдущие записи сохраняются. Интерфейс в истории — результат выбора маршрута на момент обнаружения; это не проверка VPN или правил файрвола. Следующие проверки маршрутов записываются в журнал.

Поддерживается наблюдение только IPv4 через системный механизм разрешения имён. Приложение с собственным DNS, DoH, кэшем или другим набором доменов может использовать адреса, которых монитор не увидел. При появлении IP между запусками монитор обнаружит его только при последующей проверке, если DNS в тот момент вернёт этот адрес. Уведомление зависит от доступности службы уведомлений пользовательской графической сессии. Данные могут быть общими для нескольких сервисов; DNS-ответ сам по себе не подтверждает принадлежность IP.

## Запуск по расписанию

В `systemd/` лежат примеры юнитов для пользовательского systemd. Это шаблоны, автоматически не устанавливаются. При настройке замените пути, установите юниты в `~/.config/systemd/user/` и включите таймер после проверки. Не включайте второй таймер, если этот монитор уже запускается по расписанию из другой копии. Пользовательский таймер работает при доступном пользовательском менеджере systemd; работа без сессии зависит от настроек системы.
